# AI 编程训练营排期

查看营期进度、每周任务和完成情况。

安卓原生版的构建、安装、通知设置与飞书跳转说明见 [Android README](android/README.md)。

在「添加营期」或「编辑」中选择本期考试周。新建营期预选第 6 周，旧记录沿用此前的第 7 周。考前提醒下一周课程，考试周发备考话术，之后恢复同周课程。

线上地址保持为 [AI 编程训练营排期](https://internal.aurange.cn/ai-camp-schedule/)。

## 提交工作琐记 Issue

安卓底部“随手记”支持文字与原图草稿、GitHub 设备授权、个人仓库选择和可靠提交。本地网页的“提交 Issue”支持富文本、直接粘贴截图、图文草稿及页面内直提，并读取同仓库真实 Issue 记录。

电脑双击项目根目录的 `启动本地网站.cmd`，保持服务窗口打开。新电脑可用 `http://127.0.0.1:8902/`；本机已有 `8899` 预览时继续用原地址，以保留该来源下的草稿。本地服务复用电脑 GitHub CLI 登录，不部署外部服务器，不把令牌交给网页。步骤见 [收集功能说明](docs/github-issue-setup.md)。正式网站本轮不发布，当前仅本地修改。

## 本地 SOP 知识库

安装本地 SOP 知识库后，将团队原文和附件放在 `AI编程SOP/`。公开仓库包含生成网站和 Android 所需的话术副本，完整原文及飞书同步稿保存在本地。`node scripts/export-android-data.js --check` 可在全新克隆中运行。

双击 `local-sop/启动本地SOP.cmd`，打开 `http://127.0.0.1:8901`。支持目录、中文全文搜索、富文本与 Markdown 编辑、草稿、历史恢复及收件箱；内容直接保存在 `AI编程SOP/`，方便 AI 修改本地文件。使用方法见 [本地 SOP 说明](local-sop/README.md)。

SOP 知识库仅监听本机，不自动操作飞书，也不自动改变 App 日程。维护规范与原文核对清单位于 `AI编程SOP/维护与入库/`。

## 开发

`index.html` 负责页面和交互，`data.js` 保存排期规则与任务内容，`cloud.js` 处理登录、同步和版本检查。

本轮内容按 2026-10-17 核对的 AI 编程 SOP 更新，具体来源与待确认项见 [资料核对清单](docs/audits/2026-10-17-sop-review.md)。第 11 周提醒毕业设计，第 12 周叠加毕业作品收集、展示与常规工作。毕业作品问卷链接只是示例，使用时须按营期和小队分别创建。

已按人工选择采用第 5～7 周考试流程，具体考试日期与场次按本期预约核对。常规答疑固定周六 20:00，问卷创建后立即把入口和查看方式交给老师，周六 14:00 截止后补充整理新增问题；作业周日 24:00（下周一 00:00）截止。结营奖励按各期方案发放。按 2026-10-26 确认，老带新话术在各营期第 3、11 周周三发布，无具体时刻；第 12 周仍在周日结营直播后群发优惠券与推广返现说明。

按 2026-10-19 的最新确认，入学档案每期新建，同期各购买渠道使用本期入口。看板新增「开营筹备」阶段，从开营日期前一个自然月开始（月末按上月末截断），提醒新建本期档案、建立小鹅通圈子与课程、建立群资料与云空间。三项任务持续跟进到完成；网站不固定展示往期入学档案填写链接。当前没有待确认的全局规则，空的「待确认事项」不会显示。

任务的阶段、标题和星期参与完成状态标识。修改既有任务标题时，用 `id` 保留原标题；修改星期时，用 `idDay` 保留原来的 `day`；调整阶段时用 `idWeek` 保留原阶段键，已有标识后续不要随文案更改。筹备任务沿用 `open` 类存储标识以兼容现有数据库，无需数据库迁移；页面显示为独立筹备阶段，旧浏览器导入也会映射原阶段标签。多个文档入口可用 `links` 数组，单个入口仍可用 `link`。

```sh
git clone https://github.com/linliliya/ai-camp-schedule.git
cd ai-camp-schedule
git switch -c feature/your-change
python3 -m http.server 8899
```

打开 `http://localhost:8899/` 预览。完成后推送开发分支，向 `main` 提交 Pull Request，由仓库所有者检查并合并。

## 发布

网站由 [okr-robot](https://github.com/linliliya/okr-robot) 统一发布。发布流程每 10 分钟检查一次本仓库的 `main`，有新版本时更新网站。GitHub 调度可能延迟，也可以由所有者在原仓库手动运行 `Publish internal tools`。

协作者无需获得原仓库的写入权限。开发分支不会发布到正式网站。

## 数据

营期和任务完成进度保存在 Supabase，团队成员登录后共同查看和修改。账号权限由管理员统一管理，页面上的「成员权限」可以进入管理页面。两个训练营的记录分别存储，互不混用。

变更通过实时订阅更新，每 15 秒也会检查一次。断网时可以查看当前页面已经读到的排期，恢复连接前不能保存。多人同时改同一条记录时，旧版本会提示冲突。

原有 `ai-camps-v1` 和 `ai-camps-done-v1` 不会被删除。第一次升级后，在原来保存过数据的浏览器中登录，点击「导入旧排期」。导入只新增团队里还没有的期数，同期已有的日期和进度不会被覆盖。旧链接也可以作为导入来源。

部署前在现有 Supabase 项目应用 `setup.sql`。已有部署可重新执行该文件，以启用各营期的考试周保存和同步。浏览器只使用公开的 publishable key，禁止放入 service role key。

## 验证

```sh
npm ci
npm test
```

测试覆盖数据库成员权限、两个训练营的数据隔离、版本冲突、任务状态、导入回滚，以及两个独立页面之间的共享行为。数据库测试在本地 PGlite 中运行，不写入线上数据。

页面使用主站 `/access/` 的统一登录和权限服务。部署时先发布主站，再发布本页面；完整安装须在建表后应用主站 `access/setup.sql`。
