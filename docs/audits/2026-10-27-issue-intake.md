## 已实现

- 安卓 1.6.0 / versionCode 10：底部“今日、营期、随手记、设置”。无营期账号也能进入随手记和个人 GitHub 配置，日程数据继续按原团队权限访问。
- 一个正文框、相册多选、缩略图移除、固定在毛玻璃导航上方的提交动作；每条最多 9 张原图、单张 10MB，保留最后一份文字与图片草稿。
- GitHub App Device Flow；手机直接请求 GitHub、展示短码、处理等待/拒绝/到期/限速及刷新。安装包只包含应用 slug/所有者这类公开信息，连接时从 GitHub 核对应用所有者和权限、发现公开 client ID；没有应用私钥、client secret 或电脑 CLI 凭据。
- 仅列出自己拥有、已授权、开启 Issues 且未归档的私有仓库；首次创建仓库跳 GitHub，用户授权后返回刷新。换号/换仓库须先提交或主动清空草稿。
- 原图写入各自仓库的附件目录，全部上传后创建 issue。重试检查 Git blob 摘要；请求结果不明时按持久化草稿标识分页核对，保留内容且不盲目重发。
- 网站顶部工具区及原登录页增加入口；独立 `issue-intake.html` 保存个人仓库和正文草稿，带入 GitHub 官方新 issue 页，由用户登录、添加图片并确认。超长 URL 改为明确的复制全文流程，不静默截断正文。
- GitHub 设备授权端点不允许普通静态网页 CORS 调用，所以网页采用官方提交页；不部署授权服务或公共代理。网页跳转不当作已提交成功，草稿继续保留。
- 更新本地维护规范：周三主动在 Codex 发起、先审方案与冲突、批准后修改 SOP/必要排期、逐条回填、待同步飞书；用户同步后手动拖至已完成。原 8 份 SOP、18 张图片、2 个视频共 28 个原文件哈希未变。
