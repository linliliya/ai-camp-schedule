## 管理员一次性注册 GitHub App（本项目已完成，保留维护步骤）

打开 [GitHub App 注册页](https://github.com/settings/apps/new)，使用 Arvvinn 登录，填写以下内容。无需服务器，不生成用于部署的密钥。

| 设置 | 内容 |
| --- | --- |
| GitHub 应用名称 | `Camp SOP Inbox Arvvinn`（名称保持这个，生成地址与手机配置一致） |
| 描述 | 手机工作琐记、话术与 SOP 细节收集 |
| 主页地址 | `https://github.com/Arvvinn` |
| 重定向地址（也可能显示为回调地址） | 留空，设备授权不用这个地址 |
| 允许通配符匹配 | 不勾选 |
| 用户授权令牌／使用户授权令牌过期 | 保持默认勾选，手机自动续期 |
| 在安装期间请求用户授权（OAuth） | 不勾选 |
| **启用设备流** | **勾选，必须启用** |
| 安装完成后 → 设置网址（可选） | 留空 |
| 更新时重定向 | 不勾选 |
| 网络钩子（Webhook）→ 活动／启用 | 不勾选 |
| 仓库权限 → 问题／议题（Issues） | **读取和写入（读写）** |
| 仓库权限 → 内容（Contents） | **读取和写入（读写）**，用于原图附件 |
| 仓库权限 → 元数据（Metadata） | 保持 GitHub 自动配置的读取权限 |
| 可以在哪些账号上安装这个 GitHub 应用？ | **任何账号**，这样同事能安装；不会公开他们的私有仓库 |
| 最后一步 | 点击“创建 GitHub 应用” |

创建完成后确认地址是 `https://github.com/apps/camp-sop-inbox-arvvinn`。同名冲突时可以改名，随后更新本地公开配置：

```powershell
.\scripts\configure-github-app.ps1 -Slug 实际slug -Owner Arvvinn
```

1.6.1 修复包已通过脚本核对 GitHub 应用所有者与权限，并把公开 client ID 放入安装包；手机无需在每次连接时先匿名查询应用信息，减少公开接口限流的影响。无需填写 Token 或应用密钥；如果修改应用配置，运行上面的脚本后重新构建 APK。配置脚本仅读取公开信息并核对所有者与权限，不读取或输出密钥。该接口不能确认 Device Flow 开关，需在 GitHub 页面确认。

官方依据：[注册 GitHub App](https://docs.github.com/en/apps/creating-github-apps/registering-a-github-app/registering-a-github-app)、[Device Flow](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app#using-the-device-flow-to-generate-a-user-access-token)、[令牌续期](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/refreshing-user-access-tokens)。

## 每个人在自己的手机连接

1. 安装本地 `artifacts/android/camp-schedule-1.7.0.apk`。不必先登录营期团队账号，直接点底部“随手记”。
2. 点右上角配置或进入“设置 → GitHub 配置”，点“连接 GitHub”。
3. 复制显示的短码并打开 GitHub，登录自己的账号，确认短码，再回 App。
4. 点“在 GitHub 授权仓库”，安装到自己的个人账号，只选择自己的收集仓库。手机需要 Issues/Contents 读写权限，不需要 Projects 管理权限。
5. 回 App 点“刷新可用仓库”，选择自己的私有仓库。没有仓库时先跳 GitHub 新建私有仓库，再把它加入 GitHub App 的授权范围，回来刷新。

App 只列出本人拥有、开启 Issues、未归档且已授权的私有仓库。每个人的授权保存在自己的手机，提交目标不会默认指向 Arvvinn。更换账号/仓库前，先提交或主动清空草稿。原营期和日程仍按原有团队权限访问。

粘贴文字、选图后直接提交。标题自动取首个非空行，每条最多 9 张原图，每张不超过 10MB（10,000,000 字节）。支持 JPG/PNG/WebP/GIF，不自动压缩；文字超过 55,000 字符会提示拆分，原文保留。成功显示编号与查看链接；失败保留草稿。结果不确定时先点“核对提交结果”。已经人工到 GitHub 核对过，也可以在清空确认中明确放弃本机草稿。

App 保存到自己仓库的 `attachments/<草稿标识>/`，图片引用进入对应 issue；重试核对同名文件的 Git blob 摘要，不重复覆盖内容。成功只清除当前稿的本机图片，不影响其他稿，也不自动删除远端附件。

1.7.0 增加“草稿”和“提交记录”次级入口。“存下这条，再记一条”会先保存当前稿；不同稿件的文字和图片独立。升级迁移原单稿，保留原标识、图片和待核对状态。旧存储不被覆盖成空稿；未提交稿全部处理前，不能更换账号。切回绑定其他仓库的草稿会恢复原目标，绝不自动改投。

提交记录先显示本机回执，连接后可手动刷新当前仓库的真实 Issue，分页读取并排除 PR。“已提交”和 GitHub open / closed 均不表示 SOP / 飞书完成；业务进度仍以电脑看板及处理回填为准。

## 网页端

网站顶部“提交 Issue”打开独立页面 `issue-intake.html`；营期登录页也有入口，可直接访问，不连接团队数据库。以下为 2026-10-28 新增的本地网页方案；线上站点尚未发布此版本。

1. 双击项目根目录 `启动本地网站.cmd`。需要 Node.js 24+、GitHub CLI 和 `local-sop` 的 npm 依赖；本电脑已具备。电脑 GitHub CLI 已登录 Arvvinn，不需要从手机复制令牌。
2. 本机已有 `http://127.0.0.1:8899/` 预览时继续打开原地址的 `issue-intake.html`，刷新即可保留该浏览器来源下的旧稿。新电脑可直接打开 `http://127.0.0.1:8902/issue-intake.html`。`localhost`、`127.0.0.1` 和不同端口属于不同存储来源，不会自动跨来源迁移浏览器草稿；已有草稿应继续使用原来源。
3. 页面显示已连接的电脑账号和目标私有仓库；已连接时配置区收起，需要修改时点“更换仓库”。每个人只提交到本人拥有、开启 Issues 且未归档的私有仓库。
4. 编辑器支持常用格式、代码块 / 表格，以及 Ctrl+V 截图、拖入和选图。每条最多 9 张原图、每张不超过 10 MB。外部网页 / Markdown 中无法导入的图片会提醒补图；不会静默抓取私有图片。
5. 图文草稿先保存在本浏览器 IndexedDB，多稿独立，旧 localStorage 数据保留。点“提交 Issue”后才上传原图并创建 Issue，成功返回真实编号并只清当前稿；其他稿不受影响。
6. 请求超时 / 回执异常时锁定该稿，先点“核对提交结果”，确认未创建才再次提交。附件路径与稿件标识稳定，已有同名图会核验内容，不盲目重复上传或创建。

“提交记录”打开时读取当前仓库的真实 Issues，支持刷新与分页、排除 PR。来源与 App 点刷新后相同；缓存会注明，读取失败不清空缓存。旧网页跳转 / 人工关联记录保留在单独折叠区，不伪装为成功记录。GitHub open / closed 依然不代表飞书同步完成。

本地服务只监听 `127.0.0.1:8902`，也可提供原网页；只允许同源及明确的 `127.0.0.1:8899` / `localhost:8899` 旧预览来源访问 API，核验 Host / Origin 与随机 CSRF header。服务只提供选定仓库的收集接口，不提供通用 API / shell 代理。GitHub 凭据留在电脑 CLI，网页不收集或保存令牌。不启用公开 CORS 代理。

静态文件本身不等于已具备直提授权；未运行本地服务时页面明确提示启动，不假装已提交。任意电脑打开线上网站直接提交仍需另行规划网页授权服务，未纳入本次，也没有部署。原 1.7.0 网页采用 GitHub 官方提交页；本次本地版替换其 UI，保留旧跳转记录以便核对。

当前网页资源为 `issue-intake.html/.css`、`issue-rich-store.js`、`assets/issue-editor.js` 与同目录许可文件；源代码在 `web-issue/`。构建使用 `node scripts/build-issue-editor.mjs`。`issue-notebook.js` 保留旧格式及迁移测试。任务话术继续使用 `task-scripts-data.js` 与 `task-scripts.js`。本机草稿不自动跨设备同步。

其他标签页更新后停止覆盖，输入仍在，可另存新稿；结果不确定的稿件必须先核对，不能通过另存跳过结果检查。图片文件随稿持久化，切稿时编辑器撤销历史也重置，防止撤销把另一稿内容带回来。关闭服务窗口后无法直提，但已保存的图文草稿仍在浏览器中。

本次自动后台启动被工具自动审批以“策略拦截”拒绝，未启动真实提交服务；需要本人双击启动脚本。代码接口及三轮浏览器流程使用隔离适配器验收，真实 GitHub 仅读取了 维护者的私有收集仓库 的记录，没有创建测试 Issue。

安卓打开任务详情，网页点击任务标题后展开详情，可以查看“相关话术”、来源和内容版本。复制只包含对外正文；有【待填项】时仍可复制，并提醒补齐后发送。围绕任务记一条时会创建新稿并带入可修改的来源，原稿保留。内容差异见 `docs/task-scripts-notes.md`。

## 每个人一次性设置电脑看板

电脑先使用自己的 GitHub CLI 登录，然后执行：

```powershell
gh auth refresh -h github.com -s project
.\scripts\setup-issue-project.ps1 -Owner 自己的账号 -Repository 自己的仓库
```

这是 GitHub 官方账号授权，需要本人在浏览器确认。配置脚本会验证当前账号和私有仓库，再创建/复用 `SOP Inbox - 仓库名` 项目；填有卡片的已有项目会保留其状态，不擅自替换。

在 Projects 页面完成以下设置：

1. 使用 Board 视图，按 Status 分列，选项为“待处理、待确认、已完成”。
2. Workflows → Auto-add to project：选择自己的收集仓库，筛选 `is:issue`，启用。
3. Workflows → Item added to project：设置初始 Status 为“待处理”。现有条目需要手动补入。
4. 关闭“issue closed → Done”等自动完成规则。飞书同步由本人确认后拖卡片，不自动关闭 issue。

Arvvinn 本人的看板已完成上述配置及现有条目补入。第 2 项由本人按 `owner/sop-inbox`、筛选 `is:issue` 保存开启；第 3 项截图显示 Status 为“待处理”，API 确认两项均启用。不需要重新授权，也不需要修改手机 GitHub App 权限。后续正常提交第一条工作记录时，可对照看板确认自动加入效果；不另造测试工作资料。

手机无需管理这些设置。每个人也可以直接让自己电脑上的 Codex 按这份说明配置。看板的查看、搜索和拖动使用 GitHub 自带功能。
