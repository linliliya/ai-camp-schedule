# 本地 SOP 实施步骤

**目标：** 交付可运行的本地知识库，使 Markdown 原文可读、可编辑、可搜索，并保留 AI 修改与恢复能力。

**结构：** Python 标准库 HTTP API 和文件存储；独立 Vite/Tiptap 前端；现有 `AI编程SOP` 作为内容根目录。本地状态与构建输出单独忽略。

- [x] `local-sop/server.py`：文档目录、原文/版本读取、全文搜索、条件保存、新建、历史与恢复、附件、静态文件；所有路径位于内容根，写操作同源，原子保存与历史备份。
- [x] `local-sop/tests/test_store.py`：用临时文件验证中文搜索、外部修改后冲突、保存失败完整性、读取旧版及恢复、路径校验，不触碰真实 SOP。
- [x] `local-sop/package.json`、`index.html`、`src/main.js`、`src/style.css`：目录、阅读/编辑、格式工具、源码、搜索、右侧大纲、保存反馈、冲突与草稿恢复、收件箱及新建、历史面板、导出；统一使用现有字体与单套图标。
- [x] `local-sop/README.md`、`start.ps1`：一键本地启动和 AI 入库指引；写明目录、端口、运行依赖、数据与状态位置。
- [x] 完成原 8 份 SOP 核对，新增维护规范与待确认清单，明确冲突和缺失，不修改正式原文。
- [x] 运行后台单元检查、前端构建与 UI 交互验证；启动正式内容的只读初始页面并截图，截图前后比较原 8 文档哈希。
- [x] 进行一轮符合现有参考的视觉评审，修复重要问题，交付可打开的本地地址及限制；保留所有修改为未提交状态。
