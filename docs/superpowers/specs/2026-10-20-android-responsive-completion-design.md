# 即时勾选与完成动效

用户报告勾选需要等待加载，要求参考小米待办或苹果提醒事项。沿用已选定的圆圈、暖白与靛蓝风格，直接修复等待链并更新完成反馈。

慢网络夹具已复现：旧实现等待权限检查、保存、再次权限检查及整表刷新后才更新圆圈，并用全页 busy 阻止其他任务操作。启动刷新后的提醒重建期间也存在 busy 已清除、active 仍阻止操作的小窗口。

点按在当前 UI 事件中立即更新显示状态并播放勾线、轻回弹、细圆环扩散及轻触感；后台仍使用原 RPC、权限与捕获的版本保存。待确认状态只保存在 ViewModel 内存，不写入提醒缓存；同一任务保存中禁止重复提交，其他任务可继续操作。失败恢复已同步记录并提示，冲突保留服务端版本，权限失效清除账号；退出时失效旧请求的界面回调。

服务器确认后的单条缓存更新即可结束保存，取消成功路径上多余的整表刷新；周期和手动刷新保持。并发成功响应按版本合并，防止旧结果覆盖较新的状态。提醒依旧读取服务端已确认的缓存。

今日列表先保留约 320ms 勾选反馈，再使用 Compose 原生列表淡出和弹性补位。初次进入列表不播放完成波纹，恢复待办或失败回退不触发成功触感。动效为本应用设计，不声称逐帧复制任何厂商实现。

参考：[Apple 提醒事项的圆圈完成操作](https://support.apple.com/en-us/102484)、[Compose 列表项目动画](https://developer.android.com/develop/ui/compose/lists#item-animations)。小米社区资料无法验证当前 HyperOS 的精确动效，未作为时间参数依据。
