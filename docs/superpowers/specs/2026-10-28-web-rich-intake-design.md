# 网页图文收集与统一提交记录：方案草稿

状态：用户已确认 A「先支持本地电脑一键提交，保持免部署」，开始本地实施；不提交、推送或部署。

## 这次要解决什么

1. 收集框支持富文本，截图可直接 Ctrl+V 粘贴，也支持拖入或选择图片；文字与截图按位置排列。
2. 网页点一次“提交 Issue”，完成图文上传与 Issue 创建，得到真实编号，不再要求跳 GitHub 二次提交。
3. 手机与电脑的“提交记录”统一读取同一账号、同一仓库的真实 Issues；待确认的网页跳转记录不能冒充提交成功。

原排期页仍保留小入口，不重做主站，不在收集页加入 SOP 自动整理功能。不提交、推送或部署现有项目。

## 当前差异的实际原因

- 网页 `issue-intake.js` 的 `renderRecords()` 只展示本浏览器的跳转 / 手工关联记录，存于 `camp-issue-notebook-v2`，没有调用 GitHub 查询接口。
- App 默认显示本机回执，用户刷新后由 `IssueCaptureViewModel.history()` 读取当前授权仓库的真实 Issues 并合并。因此手机刷新前也可能显示较旧的缓存。
- 同一仓库的真实 Issue 并没有按设备拆开，差异来自两端页面采用不同的数据来源。

## 可选实现方式

### A. 当前电脑的本地直提（推荐）

本地服务只监听 `127.0.0.1:8902`，可同时托管原网站页面。当前电脑继续使用已有 `8899` 页面，以保留原浏览器来源下的草稿；本地服务只对这两个明确的本机预览来源开放必要 CORS，其他网站不可调用。新电脑可直接使用 `8902` 上的同源页面。通过电脑已有 GitHub CLI 的登录凭据完成目标仓库核验、图片上传、Issue 创建与真实记录读取；凭据不返回网页，不放入网页存储。

不需要外部服务器或线上部署。这台电脑打开本地版本时支持直提；别的电脑也要启动自己的本地服务并登录自己的 GitHub，不能把此能力说成任意电脑打开线上网址即可使用。App 继续用原有个人 GitHub App 授权，不共享电脑的凭据。

### B. 任意电脑打开线上网站即可直提

配置网页 GitHub 登录及服务端授权中转 / 回调，管理个人会话，再提供图文上传与记录读取。使用体验最一致，但新增服务部署和维护，超出此前“免部署”的约定；必须另外明确同意后规划，不在这次默认执行。

### C. 仅富文本 + GitHub 官方提交页

图文先在本地整理，提交仍跳 GitHub 添加图片和确认；不新增授权服务，但不能满足网页一键提交与直接读取私有仓库记录的要求，不推荐作为目标方案。

## 推荐交互

- 简洁工具栏：段落 / 标题、加粗、列表、引用、链接、插图、撤销 / 重做；代码块和表格沿用编辑器已有能力，避免做完整文档软件。
- 优先复用本地 SOP 已安装的 Tiptap 版本；提交时转换为 GitHub Markdown。支持本地剪贴板截图，粘贴外部网页图文时不自动抓取无法读取的私有图片，明确提示缺失图像。
- 截图先保存在本机草稿，输入时不上传。沿用 App 每条最多 9 张、每张 10 MB 原图规则，超限明确保留已有内容。
- 图片、富文本内容和草稿标识保持对应；刷新 / 关闭 / 切稿后可恢复。旧纯文本草稿和跳转记录保留，升级失败不覆盖旧数据。
- 点“提交 Issue”后锁定当前提交，依次上传图片并保留图文顺序，成功才显示真实编号；失败保留当前稿，超时先核对既有标识，避免重复创建。
- 未连接本地服务时明确展示连接状态，不能把“提交成功”降级成跳转成功。线上静态版本不伪装成已支持直提。

## 统一记录规则

- 两端选择同一个账号 / 仓库后，刷新都以 GitHub 中的真实 Issues 为依据，排除 PR，分页加载。
- 显示真实 Issue 编号、标题、创建时间、GitHub 开关状态和最近刷新时间。设备刚提交的回执可以先显示，但联网后按仓库 + 编号去重。
- 网页原有“已打开 GitHub”记录保留为待核对记录，与真实提交记录分开说明，不能自动假设已经提交。
- 离线时明确标注缓存；授权过期 / 网络错误不清空已经显示的缓存，也不把失败当成没有记录。
- 草稿继续各设备保存，不在本次增加云端草稿同步。GitHub Issue open / closed 不代表飞书同步完成，业务状态仍以 Projects 看板为准。

## 本地服务的必要边界

只接受本机同源页面或明确允许的 `http://127.0.0.1:8899` / `http://localhost:8899` 预览来源，核验 Host / Origin 并保护写操作；不提供通用 GitHub 代理，不把任意 URL 或命令交给 shell。只允许本人拥有、开启 Issues 的已选择私有仓库，提交前显示登录账号与目标仓库。仅显式点击提交才允许远端写入。图片延续专用附件目录，不推送主项目源代码。

## 验收

- 旧纯文本稿升级、截图粘贴 / 拖入、图片顺序、刷新恢复、切稿隔离、存储失败保留输入、并发编辑冲突。
- 富文本与 Markdown 转换中标题 / 列表 / 链接 / 代码 / 表格 / 图片的往返，保留真实内容，粘贴内容不能执行脚本。
- 上传失败、创建超时结果未知、核对再试、重复点击、授权失效、仓库切换和历史分页。
- 两端在相同仓库刷新后按真实编号核对记录一致，离线缓存状态明确；不创建未经授权的真实测试 Issue。
- 网页桌面及窄屏可用；原日程、话术、App 提交及 Projects 完成规则不受影响。

## 依据

- [GitHub REST 跨域支持](https://docs.github.com/en/rest/using-the-rest-api/using-cors-and-jsonp-to-make-cross-origin-requests)：有权限凭据时可跨域调用 REST；不能由此推断静态页面已具备用户登录能力。
- [GitHub App 用户授权](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app)：网页授权 / 设备流与 REST 调用属于不同环节，网页登录 GitHub 不等于本项目网页可以读取用户凭据。
- [Tiptap Markdown](https://tiptap.dev/docs/editor/markdown) 与 [图片粘贴 / 拖入处理](https://tiptap.dev/docs/editor/extensions/functionality/filehandler)：编辑器支持内容转换与文件事件，文件持久化和上传仍需本项目实现。
