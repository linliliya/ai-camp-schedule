# Android 1.4: readable workbench, Chinese type and progress

The user approved the high-contrast workbench design proposed in chat, and explicitly requested downloaded comfortable Chinese fonts and a redesigned progress area whose 100% value aligns correctly. This authorizes implementation without another approval round.

Use white cards, cool light-gray canvas, dark ink text, a gray-blue primary and clear semantic red/orange/green. Keep Morandi accents on camp/phase labels. Reduce card radii and shadows; task titles 15–16sp, explanations 13sp, metadata 12sp. Retain native Compose components, source-backed glass navigation with a stronger readable tint, native camp creation, and immediate circular completion feedback.

Compare official MiSans and HarmonyOS Sans original fonts against the bundled Noto-derived subset. Choose the more comfortable mobile sans after checking actual font files, permitted app embedding and visible Chinese/numeric samples. Bundle original unmodified files with attribution and full license; avoid subsetting where the license forbids changes. Explicitly map regular and medium/semibold faces, avoiding synthetic heavy bold. Remove the superseded bundled font assets.

Replace the large colored hero and fixed 78dp ring with a compact white Today summary: pending/all-done/empty heading, independently centered percentage capsule, meaningful completed/overdue/follow-up counts, and a slim horizontal progress bar. The old ring had no dedicated text metric treatment and fixed space for three digits, percent sign and a second line. The new percentage uses natural width, center alignment, explicit line height, no font padding and font-scaling-aware minimum sizing. A genuine zero-task day shows an em dash, not 100%. 100% uses a green complete state and full bar. Keep UI statistics immediate while confirmation persists asynchronously.

Verify normal, partial, 99%, 100%, zero tasks, and large-font rendering in the dedicated CampSchedule emulator. Assert percentage placement and complete/empty semantics, contrast of meaningful text/status pairs, and regress native camp creation, completion responsiveness, calendar/filters/settings, reminder delivery, signed APK and upgrade persistence. No production camp writes and no Xiaomi hardware performance claims.

The user's follow-up asks for a restrained English font treatment inspired by Claude's website. Use an independently licensed serif (Lora, also listed in Anthropic's published brand guidance) for a small English heading and percentage numerals. Do not claim it is Claude's exact proprietary web font. Chinese remains the primary language. Bundle Lora's OFL and preserve a clear contrast between editorial accents and task content.

Regression testing exposed a previously intermittent cache race: separate LocalStore instances share snapshot.json but had only instance monitors; an AtomicFile reader could delete another instance's in-flight .new file. Both cloud acknowledgements succeeded while the second local record disappeared. Add one process-wide snapshot lock covering read/write/delete, retain asynchronous network behavior, and verify with a concurrent two-store regression and the existing slow-save scenario.
