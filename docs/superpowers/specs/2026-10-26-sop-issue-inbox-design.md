## 已确认的使用方式

1. 新建个人 GitHub 私有仓库收集工作琐记、话术、SOP 细节。账户为 Arvvinn，创建前必须告知用户。已履行告知并创建 `owner/sop-inbox`，Issues 开启。
2. 功能融合进原安卓 App，底部顺序为“今日、营期、随手记、设置”。
3. 用户在手机 ChatGPT 网页整理文字后手动复制粘贴。不接收系统分享，不自动读取或导入 ChatGPT 对话。
4. 提交页保留正文输入框、添加图片入口、提交按钮。标题自动取第一行，不要求填写分类或 SOP 关联字段；由 Codex 后续整理。
5. 图片从相册多选，显示缩略图并可移除。每条最多 9 张，保留原图、不自动压缩，单张超过 10MB 提示换图。
6. 最后一份文字及图片草稿自动保留，下次打开可继续编辑。不增加草稿列表或手机提交记录页。
7. 图片全部上传成功后才创建 issue；图片存入同一个私有仓库，并在对应 issue 正文显示。
8. 提交成功后清空正文及已选图片，显示 issue 编号；失败保留文字和图片。网络中断、结果不明确时先核对 GitHub，再决定是否重试，避免重复创建。
9. 已确认各人使用 GitHub App 设备授权：App 显示短码，用户在 GitHub 官方网页输入并确认，回 App 选自己的仓库。手机直连 GitHub，无自建授权服务器，不手动填写 Token。只授权所选仓库 Issues 与文件内容读写；原用户的 sop-inbox 不固定为同事的提交目标。
10. 电脑使用 GitHub Projects，在浏览器打开。只作为看板，不另做电脑软件，不加入 AI 整理、入库或改排期按钮。
11. 看板仅三列：待处理、待确认、已完成。新提交进入待处理，冲突或缺失信息进入待确认。
12. Codex 完成本地入库后移到待确认，注明“待同步飞书”。用户手动同步飞书后，亲自把卡片拖到已完成。
13. 周三由用户主动在 Codex 发起本批整理，不自动定时修改，不要求预设固定时刻。
14. Codex 先列入库方案与冲突，用户确认后再统一修改本地 SOP 和涉及的排期。
15. 每条 issue 回填改动位置、修改内容和待同步飞书的内容。
16. 话术、说明文字调整只更新 SOP；新增任务或改变执行时间、教学周次时，同步更新网站与安卓 App 排期。时间或适用范围不明确时先确认，不自行补齐。
17. 飞书由用户手动同步；保留本地 SOP 文件用于 Codex 检索与维护，不继续扩展本地 SOP 编辑器。
18. 现有网站/App 项目保持本地修改，不提交、不推送、不部署。新仓库只接收用户提交的文字、图片和处理记录，不上传现有项目源码或整份 SOP。

## v0.2 已整体获认可的补充建议

以下已随 v0.2 整体审阅获得用户认可；新增多人场景相关的适配仍需确认：

- **正文与格式：** 至少有一行非空文字，只有图片时提示补一句说明；正文保留 Markdown 和链接，标题取首个非空行，超出 GitHub 标题限制时只截短标题，正文不删减。图片支持 JPG、PNG、WebP、GIF；其他格式提示换图，不自动转码。大小上限按 10,000,000 字节计算，界面显示 10MB。
- **整理范围：** “处理本周待处理的 issue”理解为本次处理所有仍在待处理列的记录，包括往周遗留；用户指定编号或日期范围时以当次指令为准。待确认与已完成卡片不自动重新入库。
- **完成状态：** 用 Projects 卡片的状态表示进度。首版拖到已完成只改变卡片状态，不额外自动关闭 issue，也不根据 issue 被关闭就自动宣布飞书已同步。
- **界面与验收：** 沿用原 App 字体、配色和原生组件；看板使用 GitHub 自带查看、搜索和拖动能力。先交本地 APK 和看板地址，用户用一条明确标记的测试记录验收；不把真实工作数据当测试夹具。

后续如需修改这些默认方案，先更新文档并确认变化。

## 完整流程

ChatGPT 整理 → 用户粘贴文字、选图 → App 上传图片并创建 issue → Projects 待处理 → 周三用户发起 Codex 整理 → Codex 提方案、列冲突 → 用户确认 → 本地 SOP 与必要排期更新、检查 → issue 回填处理记录 → 待确认（待同步飞书）→ 用户手动同步飞书 → 用户拖至已完成。

冲突未解决的条目停留待确认，并注明具体问题，不假装已经本地入库；其他已确认条目可按本批批准范围独立处理。

## 新增多人 GitHub 配置

已确认新的方向：App 可分享给同事；手机端应方便连接使用者自己的 GitHub，账号、授权和提交目标不能固定为原用户。已确认每个人提交到自己的仓库，各自管理资料与看板，不采用共享团队仓库。已确认使用 GitHub 官方网页授权；已确认已有仓库在 App 选择，没有仓库则跳转 GitHub 创建私有仓库、回来刷新选择；App 不自动创建仓库。已确认换账号/仓库前有草稿时，先提交或由用户主动清空再切换。已确认不部署服务，采用手机直连 GitHub 的设备授权。电脑看板初始化及无营期账号的入口衔接按实施计划第 10 节确认。新要求不改变电脑仅作为看板、Codex 负责整理、用户手动同步飞书后标记完成的基本流程。

已确认技术路径为 GitHub App Device Flow。App 获取短码、用户在官方网页确认、手机直接获得并续期令牌，不需要自建服务器、域名、Netlify 或数据库。需在 GitHub 一次性注册应用并开启 Device Flow，普通用户只授权安装到自己的仓库；当前不注册、不部署；本地功能代码已按用户授权实现。

已确认并实现：无营期账号的同事可独立进入随手记与 GitHub 配置，原团队日程权限继续独立。网站顶部工具区和登录页均提供提交入口；独立页面直接使用 GitHub 官方提交页完成文字、图片与登录，避免静态网页 OAuth 跨域限制且无需部署服务。
